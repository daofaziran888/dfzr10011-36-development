# 分布式采集调度引擎

面向大规模数据采集团队的分布式采集调度引擎。覆盖采集节点集群管理、任务分片调度、结果聚合归并、节点健康监控、采集流量均衡、断点续采恢复与全局采集看板的完整分布式采集链路。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 采集存储分层归档链路

`storage` 模块在策略维护之外，串起了“扫描文件 → 校验格式 → 计算保留期准入 → 分层归档 → 聚合准入”的完整链路。

- **策略版本**：策略记录带 `策略版本`。一次归档只读取一个版本下的层级规则，
  归档结果、清理清单、恢复清单和聚合侧引用都带同一个版本号，可按版本核对。
- **文件与规则**（`app/services/storage_policy.py`，共用判定）：
  文件格式必须在支持范围（parquet/orc/json/avro），按文件年龄匹配准入天数最低的
  已生效层级，并按该层级的保留天数计算 `到期日期`。空文件单独显示为空文件层级；
  格式不支持、缺少创建时间、没有可用层级覆盖等情况一律不入准入，并给出可读的清理依据。
- **归档结果**（`GET /api/storage/archive`）：写入 `storage_archive`，包含
  `归档编号/策略版本/归档层级/目标层级/保留天数/到期日期/准入结果/归档状态/
  分层依据/清理依据/冲突处理/清理状态/数据改写`。被恢复检查点引用的文件
  `数据改写` 恒为 `false`、`内容处理` 为“保持原样”，不删除也不改写。
- **冲突处理**：过期文件同时被清理计划和恢复检查点引用时按终态优先级处理：
  - `恢复终态优先`：归档结果显示 `恢复保留`，清理清单出现 `已延迟` 项并带延迟原因，
    恢复清单保持原层级；
  - `清理终态优先`：归档结果显示 `已清理`，恢复清单出现 `新层级入口`，
    `目标层级/恢复入口/文件编号` 指明恢复改走哪一层。
- **历史回填**（`POST /api/storage/backfill`）：缺少分层依据的历史记录按文件原层级
  回填；失败记录跳过并继续处理后面的记录；迁移记录按 `归档编号+文件编号` 幂等，
  重复回填不会生成第二份迁移记录。
- **聚合侧**（`GET /api/merge/storage-admission`、`GET /api/merge/storage-archive`）：
  归档结果写入新增存储分层准入待处理队列；结果聚合只引用同一策略版本下仍可用的
  层级，并输出按层级和清理依据的聚合结果。`POST /api/storage/merge-sync` 与
  `POST /api/merge/storage-sync` 两个入口都会同步刷新准入清单与归档结果快照。
- **并发读写**：归档、清理重建、回填与聚合刷新共用 `store.lock` 同一把锁，
  读侧只看已提交的归档结果与准入清单，不会读到半写入的层级。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
